## Resolved R3 — P1: response-to-local transfer advanced display baseline without persisting that generated prefix

- Location at review: `Chat/Background/IOSChatBackgroundResponseResumer.swift:235-277`; downstream `IOSChatBackgroundExecutor.swift:470-540`, terminal saves and `IOSConversationStore.saveBackgroundCompletion:683-731`.
- Concrete reachable sequence: a resumed server response creates an assistant message containing text and a pending tool. continueCompletedDetachedResponse persists a continueModel payload whose displayMessages include that new assistant and starts the local loop; it does not persist those messages to the conversation. The conversation still has the original user/history baseline. After the tool and another provider turn, terminal saveBackgroundCompletion uses the advanced job.displayMessages as baseMessages. Because the actual conversation is shorter, the merge branch appends only completedMessages.dropFirst(baseMessages.count), omitting the recovered assistant and its tool result altogether. A subsequent model failure saves only the new error; successful completion also loses the generated prefix. The current transfer regression stops at the next model request and cannot catch this durable loss.
- Required narrow fix: preserve the distinction between current round display/upload snapshots and the original baseline against which this run's generated messages must be persisted. Alternatively, checkpoint the recovered display to the conversation before advancing the baseline, but explicitly handle the conversation-written/payload-write-failed retry window so another replay does not append a new UUID copy of the same response. Do not solve this by generally resurrecting baseline messages in saveBackgroundCompletion; that would undo deliberate user deletions in unrelated concurrent-write cases.
- Regression: transfer a response with text + tool and known assistant id, let the tool finish and the next provider fail, await the real terminal save, then reload the conversation and assert the original assistant id/text/tool output plus exactly one error. Cover successful next turn as a control. If advancing conversation first, additionally test transfer-payload failure then retry for duplicate-free prefix preservation.
