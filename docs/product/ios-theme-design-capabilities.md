# iOS 主题设计能力盘点

本轮将生成主题从固定纸色搭配扩展为完整设计配方。入口仍是「外观 → 生成并试穿」，由 `theme_pack_status` 读取能力，再通过 `theme_pack_import` 试穿。用户点「套用」后才保存；还原恢复原主题。旧主题文件仍可导入，切回内置包会移除自定义设计。

## 在现有主题上修改

外观页新增「修改并试穿」，与「生成并试穿」分开。修改请求会把当前主题 id 交给 Agent，要求只调整明确提出的字段。聊天里直接提出微调需求时，也使用同一套工具入口。两项操作使用相同字数和固定图标栏，保持纵向对齐。

- `theme_pack_status` 可传 `id` 查看指定已安装主题或内置主题。返回的 `base` 是待编辑配方；省略 `id` 或传 `current` 时优先返回当前试穿候选，否则返回已应用主题。`current` 继续表示已保存的试穿前状态，`try_on` 表示候选。
- `theme_pack_import` 传 `base_id` 后进入局部修改模式，其余参数只提供变化部分。对象逐字段合并，省略的字段原样保留。`patterns`、渐变颜色数组整体替换，修改一项时需一并保留其它项。
- 自定义主题保持原 id；点「套用」后覆盖原库条目，不增加一个新主题。内置主题首次修改保存为自定义副本，后续使用返回的 id 或 `current` 继续修改同一副本。
- 试穿不提前写入原主题。继续微调会继承最新候选；「还原」恢复整轮试穿前的外观，校验失败不会撤掉已有预览。
- 可用 `null` 移除 `design`、浅/深色配色覆盖、`gradient`、`components` 或单个组件属性，用 `patterns: []` 清空纹理。内置或旧主题可直接只改组件；缺省的浅/深色配色继承原画布与首页颜色，不会为改圆角重新生成配色。首次添加某一模式的自定义配色需提供五个颜色字段；渐变仍需两套配色进行对比度校验。
- 当前主题的 id 与名称随应用状态持久化，两个主题即使视觉完全相同，也会按明确选中的身份继续编辑。手动改变画布或强调色会解除原身份；重复选择同一值不丢失身份。

例如保留主题其余设计，只修改卡片圆角和浅色边框：

```json
{
  "base_id": "rain-bookstore",
  "design": {
    "components": { "cardRadius": 12 },
    "light": { "border": "#BBBBBB" }
  }
}
```

不传 `base_id` 时仍是新建，需要原有九个必填字段和新的 id。新建与修改都复用现有前台试穿审批，后台和嵌套执行权限没有扩大。

## 已开放

| 设计对象 | 可设计内容 | 实际作用位置 |
| --- | --- | --- |
| 浅色与深色配色 | 分别定义背景、卡面、主文字、次文字、边框；次级表面由新配色派生 | 使用 AmberTheme 语义色的原生页面、卡片、文本和边框 |
| 强调色 | 任意 RGB 色与搭配的文字色 | 强调按钮、用户气泡等；用户气泡已消费配套文字色 |
| 渐变背景 | 浅深各 2–4 个色阶，任意方向角度 | 已接入主题背景的页面 |
| 组合花纹 | 点阵、网格、斜纹、十字、波浪、圆环，最多 3 层 | 同上；每层独立颜色、透明度、间距和尺寸 |
| 背景范围 | 首页、首页及设置外壳、已接入的应用页面 | `homeOnly` / `shell` / `appWide`；颜色仍由全局语义色驱动 |
| 卡片形状 | 0–32 pt 圆角 | 首页卡片及使用卡片圆角令牌的聊天/工具卡组件 |
| 气泡形状 | 0–28 pt 圆角 | 用户消息气泡及长按预览 |
| 控件形状 | 0–28 pt 圆角 | 共用玻璃按钮、首页玻璃控件、聊天输入栏 |
| 描边 | 0–3 pt 宽度，颜色使用主题边框色 | 首页继续卡、空态卡、玻璃控件、聊天输入栏、用户气泡 |
| 卡片阴影 | 0–0.35 强度、0–24 pt 扩散 | 使用首页卡片投影令牌的卡片 |
| 品牌 | 系统字标、像素 AMBER、衬线字标；也可提供 1–16 字符自定义字样 | 首页及选择跟随品牌的账户/关于区域 |
| 品牌排字 | 20–40 pt 字号、-2–6 pt 字距 | 文字字标；像素字标保留原像素轮廓 |
| 界面字体 | 系统、圆润、衬线、等宽 | 已使用 Chrome 字体的标题/标签；设置可选择跟随 |
| 快捷图标 | Phosphor 实心、像素、原生描边 | 首页五个固定功能入口 |
| 玻璃质感 | 标准、柔和、实底衬托 | 现有原生玻璃入口；保留系统玻璃交互 |
| 空态与品牌呼应 | 空态纹理、账户品牌呼应开关 | 现有空态/品牌展示入口 |

完整设计放在可选 `design` 对象中：`light`、`dark`、`patterns` 必填（花纹可用空数组），`gradient` 和 `components` 可省略。原有 `paper` 是兼容基础。精确参数范围由工具状态与 schema 返回。

## 覆盖边界

- `appWide` 指已经使用 `AmberThemePageBackground` 的页面，包括聊天、议会、小应用外壳、WebMount 和部分小说页面；不是对所有系统弹窗、网页内容或第三方界面强制换肤。
- 圆角、描边等通过上述现有共享入口接入，尚未把每一个写死圆角的业务页面逐一改造成主题组件。
- 字体风格作用于界面标签，不覆盖用户单独设置的聊天正文字体、字号。
- 花纹是静态矢量绘制，密度和层数有限。浅深主文字对背景与卡面对比至少 4.5:1，次文字至少 3:1，渐变色阶也做主文字对比检查。

## 后续仍可扩展的能力

| 能力 | 本轮状态与原因 |
| --- | --- |
| 本地壁纸、照片背景 | 尚未实现。需要资源导入、主题文件携带资源和清理生命周期 |
| 自定义 SVG／图片图标、品牌图像 | 尚未实现。当前提供可可靠渲染的内置图标和文字；自由资源需要格式校验和持久化 |
| 自由路径、任意形状装饰 | 尚未实现。当前六种可组合图案不等于任意矢量绘图 |
| 自定义字体文件 | 尚未实现。需要资源安装/导出机制；本轮支持系统四类字体设计 |
| 全部业务卡片独立形状和按钮样式 | 部分接入。可继续沿真实业务组件逐项开放，无统一覆盖承诺 |
| 页面重排、导航结构、聊天气泡宽度、段落间距 | 尚未交给主题。涉及交互布局和滚动测量，需要独立需求与运行验证 |
| 动态背景、粒子、主题转场 | 尚未实现。需要单独处理耗电、动画性能和减少动态效果偏好 |
| 网页、小应用内部内容、系统控件的任意换肤 | 不由这些原生主题槽统一控制，各有自己的渲染边界 |

## 实现入口

- `iosApp/iosApp/AmberThemeDesign.swift`：设计模型、校验、渐变/花纹渲染。
- `iosApp/iosApp/AmberThemePack.swift`：主题文件、导入导出、预览、背景、品牌和快捷图标。
- `iosApp/iosApp/PlaceholderViews.swift`：运行时持久化、语义色和共享组件参数。
- `iosApp/iosApp/IOSThemePackToolService.swift` 与 `ai-core/.../Tool.kt`：模型可读取和调用的工具协议。
