# 现有 VPN 回环与蜂窝启动验证

目标：Amber 可复用已连接且支持本地回环的 VPN，在启动、失败、取消和结束时均不修改或关闭该 VPN。既有内置连接保持默认。纯蜂窝支持另行实测，不由连接方式选项推断。

## Phase 1：路由与生命周期

- 持久化内置/现有 VPN 选择，只在连接操作空闲时允许切换；切换清除旧检查结果和应用查询缓存。
- 首次配对、独立应用查询与 Runner 启动均传递相同的路由模式；外部模式不调用 Amber VPN 的读取、准备、启动或停止。
- 原生根据内核实际路由绑定唯一有效 utun，覆盖初始 RemotePairing 及随后动态 TLS 端口；不回落到普通网络接口。
- 验证默认路径、模式传递、成功/失败/取消与清理；独立 review 调用链。

## Phase 2：设置与交付

- 连接方式可见、持久化并被生产消费；外部模式说明代理需启用回环，选择本身不表示已连接。
- 外部模式隐藏 Amber 配置准备动作，配对/应用查询/检查自动化使用新的准备门禁；结束文案只报告本次会话状态。
- 检查普通、窄屏、大字号及失败状态截图，完成一次有限可维护性审查。
- 在排除既有 Intelligent UI WIP 的隔离工作区构建；安装前后核对原有会话及关键设置保留。

## Phase 3：真机与 5G

- 已有回环 VPN 下，尝试真实启动、认证、读树与结束，核对代理仍由用户管理。
- 单独尝试离线建链后恢复蜂窝。成功必须包括恢复后继续观察、动作及联网请求；只显示 VPN 已连接不算完成。
- 如遇设备锁定、开发服务不可用、外部回环未启用或网络切换使会话失效，记录具体边界，不增加盲目重试、不声称蜂窝支持。
