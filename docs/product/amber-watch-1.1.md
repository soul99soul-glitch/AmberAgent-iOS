# Amber Watch 1.1 增强计划

日期：2026-09-30。基线：[Amber Watch 1.0](amber-watch-v1.md) 已完成的提问、记事、任务控制、近期动态、快捷动作、表盘入口，以及本轮已完成的「跟随 iPhone 主题强调色」。

目标：把手表从「打开 App 才能用的遥控器」变成「系统在合适时机把 Amber 推到你面前、单手能完成、有自己性格的腕上助手」。

## 原则

- 复用 1.0 已打通的链路（请求 ID、回执、runId/decisionId 校验、审批边界），新能力只加入口或展示层，不另建执行路径。
- 不越过 1.0 的边界：手表只批准可完整表达的低风险操作；保存记事不等于调用 AI；Watch 不同步凭据与 HealthKit。
- 精准实现：不做未要求的开关、兜底和抽象；每个设置项都对应一个真实可感的差异。

## Phase 1 · 手表更「活」（仅手表端）

| 编号 | 内容 | 完成条件 |
| --- | --- | --- |
| F2 | 智能叠放相关性 + 新表盘样式 | 当前任务组件按真实阶段给出 `TimelineEntryRelevance`：等你回答最高，运行中次之，刚结束短暂保留，空闲为 0。当前任务组件新增 `.accessoryCorner`、`.accessoryInline`；「问 Amber」新增 `.accessoryCorner` |
| F3 | 双指互点 | 每屏只有一个主操作：首页「问 Amber」、输入页「发送/保存」、待回答卡片的首个可执行选项 |
| P1 | 表盘组件跟随主题色 | 手表把当前生效的强调色（受「跟随 iPhone 主题色」开关控制）写入组件缓存；组件图标与运行态颜色使用它，着色表盘下由系统着色（`widgetAccentable`）；完成/失败/过期保持语义色 |
| P3 | 触感分级 | 完成＝success，需要你＝notification，失败＝failure；三类事件可分别关闭，总开关关闭时全部静默 |
| P4 | 状态动效 | 首页 Amber 标识在运行中缓慢呼吸；成果卡状态图标在状态切换时弹跳一次；减少动态效果或低亮度常亮时不动 |

## Phase 2 · 从遥控器到助手（手表 + 手机）

| 编号 | 内容 | 完成条件 |
| --- | --- | --- |
| F1 | Siri / 快捷指令 | Watch target 提供三个 App Intent：「问 Amber」（可带问题，打开输入页预填，检查后发送）、「记一下」（直接保存为手表记事并返回结果）、「运行快捷动作」（选择手机下发的快捷动作，打开确认页）；提供 App Shortcuts 短语 |
| F4 | 快捷动作填空模板 | 问题中含 `{输入}` 或 `{input}` 时，手表先让用户输入填空内容，展示填好的完整问题后发送；手机按原模板填入后执行；无占位符的快捷动作行为不变；旧版手表发送原文仍被接受 |
| F5 | 记事交给 Amber | 记事详情提供「整理成要点 / 提取待办 / 扩写」，生成预填的新问题，用户检查后发送；原记事不变 |
| P2 | 回答长度偏好 | 手机 Apple Watch 设置里选择「默认 / 一句话 / 三句话 / 要点」；只作用于手表发起的新问题、追问和快捷动作，在消息末尾附加可见的简短要求 |

## Phase 3 · 通知、声音与布局（需真机验收）

| 编号 | 内容 | 完成条件 |
| --- | --- | --- |
| F6 | 可操作通知 | 「需要你确认」的批准通知正文显示操作类型（如「搜索网页」，不含查询等参数），附「拒绝」，手表可批准的低风险决定另附「允许」（iPhone 锁屏需解锁）；按钮携带 runId/decisionId，走与手表相同的 `handleWatchAction` 校验，过期决定被拒绝。问答类决定的选项即问题内容，按 1.0 隐私规则不放进通知 |
| F7 | 朗读回答 | 任务回答节选与成果详情提供「朗读 / 停止」；使用长音频策略，由系统引导连接耳机，不从手表外放；离开页面即停止 |
| P5 | 首页模式 | 手表设置可选「成果优先」（默认，现状）或「提问优先」（问 Amber 按钮移到顶部，成果卡与其他入口在下方滚动区） |

## 每个 Phase 的验收

1. 新增行为有对应单元测试，关键修复先红后绿。
2. iOS 单元测试（Watch 相关）通过；`AmberWatchApp` 与 `AmberWatchWidgets` 编译通过。
3. 独立子代理审查：逻辑闭环、调用链路完整、UI 错位/对齐/边距/尺寸；只修确认的问题。
4. 新文案补齐六语言。

## 不在本轮

今日简报（缺结构化数据）、健康/运动情境（改变隐私边界）、手表独立联网、实时语音。

## 实施记录（2026-09-30）

三个 Phase 均已实现，每个 Phase 结束后由独立子代理审查并修复：

- Phase 1 审查 7 项（中 4、低 3）已修：冷启动呼吸不启动（改 `phaseAnimator`）、抬腕重复弹跳（`symbolEffectsRemoved`）、过期状态仍参与智能叠放排序、断连恢复后重复触感（改按手机原始 phase 比较）、未读点跟随主题色、主题色开关移到「显示」组首行、高风险审批不启用双指互点。
- Phase 2 审查 9 项（中 1、低 8）已修：参数化短语首启不注册（`initial: true` + 无参短语）、模板计数按填好后的全文、模板草稿改用独立键 `quick-fill:` 避免吞入旧整句草稿、超长记事不显示「交给 Amber」、批准通知标题改为「需要你确认」、通知按钮被拒时补发结果通知、切换语言重注册通知按钮、存储失败与缺值分开报错、手机端模板/回答长度逻辑补测试。
- Phase 3 审查 5 项（高 1、中 1、低 3）已修：落腕后朗读被隐私占位打断（停止改挂在页面路由上，并加 `WKBackgroundModes: audio`）、提问优先首页底部空带与左右不齐、朗读激活中途取消时音频会话残留、模板删除占位符后旧草稿仍按模板处理。

验证：Watch 相关单元测试全部通过；`AmberWatchApp`（含 `AmberWatchWidgets`）编译通过；42mm 模拟器预览截图逐项检查。

仍需真机验收：智能叠放实际排序、双指互点、Siri 短语识别、通知在手表上的按钮与镜像、蓝牙耳机朗读与落腕后持续播放、表盘组件在各表盘着色模式下的效果。
