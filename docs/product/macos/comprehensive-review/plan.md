| R6 · P2 | 编辑消息重新发送失败时弹窗仍无条件关闭，未提交的编辑稿丢失 | Editor 的 onSubmit/dismiss、Transcript 忽略 Task 结果、Workspace 配置/持久化失败路径经两名 UI reviewer 与主 agent 交叉追踪 |

## 顺序与验收

| Phase | 工作 | 本阶段结束条件 |
| --- | --- | --- |
| 1 · 公开网络边界 | 修复 R1，复用既有公开地址策略，覆盖空/私网/回环/Fake-IP/混合/公开结果，核对初始与重定向入口 | 受影响测试通过；独立 subagent 检查调用链和变更范围 |
| 2 · 消息与文件完成语义 | 先修 R2，再修 R3，避免同时编辑 Workspace；修复 R5 的本地保存恢复；检查取消、重试、原 owner、退出等待与内部 flush 自等待 | 红灯测试转绿；相关既有测试通过；独立 subagent 检查消息状态、UI 可恢复入口、文件保存与取消链 |
| 3 · 启动路由与界面 | 修复 R4：启动时安装 delegate、窗口绑定后消费有效目标；保持通知发送开关与原有加载/删除提示。修复 R6：编辑持久提交成功才关闭，失败保留稿件并显示错误，提交中防重复 | 路由时序、编辑提交成功/拒绝/写失败测试，构建与独立 review；实窗及必要窄窗组件截图检查，不凭 inactive 绘制或旧图判错 |
| 4 · 产品集成与交付 | 全套共用 Runtime 回归，同源 Preview 构建/实窗检查/签名打包；尝试正式 Shared/Native、真实 provider 和系统能力验收；更新问题、证据和剩余阻塞 | 所有已确认修复闭环，独立最终 review；正式验收有证据才关闭，不能用 Preview 代替 |

本轮基线 227 个 Swift Runtime 测试通过。正式 Xcode 构建当前在拉取 iosMath 时被现有 127.0.0.1:7897 代理阻断；Gradle wrapper 的缓存锁写入被系统拒绝，尚未进入编译。继续完成其余阶段，不制造 Shared 替身，不更改系统权限、代理或签名保护来绕过限制。

这份计划必须先经独立复核，再开始生产代码修改。每个阶段完成后记录实际测试和 subagent 复核结果；正式产品完成状态取决于 Phase 4 的真实验收结果。
