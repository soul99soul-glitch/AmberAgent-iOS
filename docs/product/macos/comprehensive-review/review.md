# macOS 产品全面审查与修复

日期：2026-10-23。当前产品是本仓生成 Shared.framework 的原生 macOS 客户端，主要负载是一名用户、多会话、流式生成与并行工具任务。本轮以实际入口、状态所有者和持久化终点为依据，先复核问题，再按 [计划](plan.md) 顺序修复。

## 确认真问题与修复

| 编号 | 严重度 | 具体问题 | 最终行为 |
| --- | --- | --- | --- |
| R1 | P1 | 公开网页工具解析 DNS 后丢弃结果，初始请求及重定向都可能接受非公开地址 | 同一校验要求解析结果非空且全部通过已有公开地址策略；不新增 DNS/网络框架 |
| R2 | P2 | 工具轮边界接受排队用户消息后取消，将上一条已完成回复标为取消；用户消息仍生成中且无法重试 | 用户消息保持完成；为未产生的回复保留独立取消状态，原重试链只提交该用户消息一次 |
| R3 | P2 | 工作区文件导入等已接受写操作没有纳入退出等待 | 七个写入入口登记实际任务；退出等待完成。会话导出只等待内部会话 writer，避免等待自身 |
| R4 | P2 | 通知 delegate 安装过晚；窗口未绑定时丢弃冷启动目标 | 启动时注册；暂存有效目标，绑定并加载后打开原会话；旧等待不能抢回新目标，不改变通知授权或发送开关 |
| R5 | P2 | 图片生成成功但本地保存失败时，唯一暂存结果仍被删除，重试需再次联网 | 复用现有 history 保存原 owner 与剩余文件；本地重试只搬运剩余图片；成功逐图清理，重启及多 owner 可恢复 |
| R6 | P2 | 消息编辑提交失败仍关闭弹窗，编辑稿丢失 | 持久提交成功后关闭；配置或写失败保留文字及可见错误，提交中禁止重复操作；后续模型失败不倒推编辑提交失败 |

R1 经真实生产 preflight 复现，未发送 HTTP；R2、R3、R5 均先用当前真实 Runtime/repository 的独立测试取得业务断言红灯，后验证转绿。R4 对照启动/窗口绑定链和 Apple 的 [通知 delegate 要求](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/delegate) 复核。R6 经两名 UI reviewer、主 agent 和计划 reviewer 交叉追踪提交与关闭路径，不以 Task 创建或完成猜测提交成功。

## 排除的假阳性

- Gemini 工具请求有 engine 专用分流；不能因通用 transport 只列 OpenAI/Claude 就报未接入。
- Recipe 的拒绝/失败结果会阻止后续步骤；协作执行也使用独立 execution ID。
- 备份在会话持久化失败时仍可从完整内存快照抢救；这不是丢数据。
- 恢复会覆盖新会话 UUID，并有尝试 ID、文件与记忆回滚路径。
- Settings 实窗关闭重开仍保留未保存 draft；SOUL 关闭也有保护，测试稿均已还原。
- 真实 OAuth client 保存前检查取消；不合作 mock 的结果不能直接作为生产故障。
- UI 没列出某个 backup 禁用条件，不代表绕过 Runtime 的最终 guard。
- 表格首格高亮和非活动按钮的系统绘制不作为错位；跨重启 pending 指令队列没有现有持久化契约，不据此新增存储层。

## UI 与证据

修改前先采集 9 张真实 App 截图及 24 个新渲染的原生组件状态，记录于 [UI 审查](ui-review.md)。已检查聊天、知识、任务、文件、协作、Recipe、备份及设置的长文与操作区；860pt 视口的证据来自同源原生组件，未冒充实窗交互。

修复后 9 张新状态图及可复现 harness 见 [UI 修复后复核](ui-after/review.md)：排队取消后的独立回复及重试、图片待保存/部分保存/本地恢复，以及编辑器提交中、失败保稿和成功关闭。真实组件的 ⌘Return/Escape 验证重复提交与提交中关闭被阻止，两次 payload 字节相同；失败面板自然增高至 560×466，无错误或按钮裁切。空取消回复的提示已依据新图修正为“已停止，可重新生成”。独立 reviewer 与主 agent 均已亲看关键新图，未发现新的确认布局问题。

编辑器 busy 状态的禁用正文未被离屏缓存绘出，失败后恢复可见且原稿完整；尚不能通过最终实窗排除绘制差异，未据此盲改生产。截图不替代真实 provider 或系统权限验证。

## 验证边界与未完成验收

本轮修改限于 macOS 源码、测试、构建源引用和产品记录；未修改 iOS/KMP 实现、用户现有 iOS WIP、系统代理或权限。没有添加依赖、替身 Shared 或新的通用恢复框架。

- 正式构建初次拉取 iosMath 被既有本机代理阻断；使用本仓已有同 revision checkout 与项目内 DerivedData/package/module caches 重试后，模块缓存错误消失，Xcode/SwiftPM 仍硬写用户 `ManifestLoading/iosmath.dia` 并被拒绝（exit 74），未进入正式 Shared 链接。Gradle 改用已缓存的官方 9.4.1、JDK 21、项目内用户/工程缓存，离线 Native 任务仍因 `FileLockContentionHandler` 的本机 socket 被拒而退出，未编译工程。
- 最终 Preview 的 CUA 复拍返回 `Transport closed`。正常 `open -n` 尝试返回 LaunchServices -10827；实际 bundle executable 存在、0755、Mach-O arm64、严格签名有效，直接二进制启动退出 134 且无诊断输出。当前受限执行上下文无法确认最终新包实窗已打开，也不足以定位生产崩溃原因，未据此盲改启动代码。
- 真实模型、正式 Keychain、系统通知冷启动点击及正式沙盒工具往返仍未获得本轮验收证据。纯 Runtime、Preview、语法检查不能关闭这些条目。
- 既有明确产品差距仍保留：子代理独立对话/工具角色、议会多轮、SSH、固定产物架、单次请求覆盖、iOS 全量备份/CloudKit 互导、多语言与 Mac 订阅。没有新增空入口或把它们算成本轮已完成。

本轮确认的代码问题已修复；正式产品尚不能标记完整验收。所有原始测试、构建尝试和最终交付校验保存在 `evidence/` 与 `delivery.json`。
