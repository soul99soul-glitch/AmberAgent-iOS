## 已确认问题

**P2：编辑重发失败时，编辑器提前关闭，修改稿丢失。**

`DesktopMessageEditor` 的重新发送按钮调用 `onSubmit(text)` 后无条件 `dismiss()`；Transcript 提供的闭包调用 `workspace.editAndResend`，没有消费其可选任务或分支保存结果。若模型配置/凭证校验同步失败，方法返回 nil；若 `storage.editMessage` 异步失败，Runtime 保留原分支并显示错误。两条路径都没有保存编辑稿，编辑器却已经关闭。

此问题由第二名独立 UI 源码 reviewer 提出并交叉复核；现有分支测试验证原消息保留，未验证编辑器草稿生命周期。最小修复应在真实分支保存成功后关闭；失败时保留文本并显示错误。只检查 Task 非空仍会遗漏异步写入失败。失败界面的真实 UI 复拍待修复验证阶段补充，本轮未伪造失败截图。

## 已排除的假阳性

- Settings 关闭会丢草稿：实窗改名称、关闭并重开后，draft 和未保存状态均保留。测试名称已恢复，未保存到配置。
- SOUL 分类切换或关闭绕过保护：三个分类可达，临时编辑后点击完成会显示保存/放弃/继续编辑；继续编辑保留文字。测试草稿已清空，未写入 SOUL。
- 搜索凭证读取失败后保存空字符串会擦除原凭证：`DesktopSearchSettings.save` 对非免费服务强制非空，免费服务不写凭证，不成立。
- Transcript 未将备份状态加入 UI mutationsDisabled 会直接破坏数据：最终 `mutateBranch` 仍拦截 isManagingBackup，不能据 UI 列表缺一项推断数据破坏。
- 表格首格圆角高亮、非活动 prominent 按钮的系统绘制，不作为新的生产布局缺陷处理。
