# Amber Watch 1.0 产品功能定义

日期：2026-09-08。状态：首版代码实现与自动化验证已完成，真机发布验收待完成。本文定义首版范围、交互和验收标准；实际验证证据单独记录，未勾选的验收项不代表已通过。

## 1. 产品定位

**Amber Watch 是腕上的 AI 助手：随口问、随手记、看进度、接着办。**

首版采用 iPhone 协同模式。Watch 承担输入、简短结果、任务状态和及时交互；iPhone 保有模型配置、会话、工具执行和完整结果的所有权。目标是在手机正常可达、配置有效时，一次普通短问答可以在手表上完成，不要求每次手动打开手机。

用户已选择两个优先场景：「抬腕语音提问、记事，再查看或控制手机上的 AI 任务」和「追踪 AI 任务进度、处理提醒和快捷操作」。本轮按这两个方向实施。独立联网对话作为后续产品分支。

三项体验目标：

- 抬腕数秒内能看懂当前状态；没有任务时也有明确可用的入口。
- 提问、记事、继续回答都从首页或表盘入口进入，避免深层菜单。
- 发送、收到、运行、完成分别有真实状态；断连和失败不丢输入，也不冒充成功。

Apple 的 watchOS 设计指南强调简短、可扫读的交互和较浅的导航，并建议充分利用表盘、通知和 Siri 等入口；本方案据此安排信息密度与入口。[Apple：Designing for watchOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-watchos/)

## 2. 开发前的实现与缺口

以下为开发前的代码核查基线，用于解释本轮改动的原因。

| 范围 | 当前事实 | 对产品的影响 |
| --- | --- | --- |
| 安装与图标 | `WatchApp` 只有 3 个 Swift 文件和 Info.plist；两个 Watch target 都未配置 AppIcon，也未包含手机图标目录 | 用户报告的无图标有直接资源和工程配置依据 |
| 首页 | 一个滚动页面，根据当前任务显示状态、决定、摘要和按钮 | 没有任务时主要只剩「没有进行中的任务」和刷新 |
| 发起请求 | 协议支持审批、回答、取消、重试、打开和刷新，没有新问题或新记事 | 手表只能参与手机已经发起的任务 |
| 输入 | 待回答状态下提供 TextField，可利用系统文字输入 | 不是主动提问入口，也没有持续语音对话功能 |
| 内容 | 单一任务快照，摘要截取至 280 字符 | 无最近记录列表，也不能把截取文字当作完整回答或语义摘要 |
| 同步 | 有 WatchConnectivity、动作超时、过期状态、requestId 和 runId 校验；互动命令不离线排队 | 具备可复用的控制基础，还缺持久的用户输入和完整的连接状态展示 |
| 审批 | 高风险操作也会生成允许/拒绝选项，部分正文只取短预览的一项 | 需要明确哪些操作适合在小屏上批准，并由手机执行端落实限制 |
| 手机接力 | 当前发送应用内 NotificationCenter 事件后即返回「已在 iPhone 打开任务」 | 接收事件不等于手机已展示目标页面，需要改成有回执的接力 |
| 系统入口 | Watch target 未包含自己的 WidgetKit 扩展和 App Intents | 手机 Live Activity 或手机快捷指令不能直接算作已完成的 Watch 产品入口 |

## 3. 1.0 必须具备的功能

表中每一项都是首版交付范围，不能只完成入口或静态展示就标记为可用。

| 功能 | 用户能完成什么 | 首版边界与完成条件 |
| --- | --- | --- |
| 正式图标与首次使用 | 在应用列表认出 Amber，第一次打开就知道下一步 | 复用现有 Amber「A」标识并适配圆形裁切；检查配对、连接、手机配置和版本兼容；未准备好时仍可保存本地输入 |
| 问 Amber | 用系统听写或文字输入发起问题，在手表看简短回答并追问 | 发送前可检查文字；新问题创建会话，追问保留明确的原会话；提供取消和失败恢复；手机忙碌时不抢占当前任务 |
| 随手记 | 记录一个想法，立即保存到手表，稍后同步到手机 | 原文保存，不必等待 AI；明确显示「已存手表 / 待同步 / 已存 iPhone」；同步失败可重试；不会自动变成提醒事项或长期记忆 |
| 任务与简短追问 | 看当前工作在做什么，回答单选或短问题，取消运行，重试符合条件的失败任务 | 显示真实阶段和更新时间；不虚构百分比或剩余时间；取消先确认且保留已有结果；所有操作绑定原任务 |
| 有边界的操作确认 | 对能够完整表达的有限操作作出决定 | 手机重新检查操作类型、参数、有效期与任务；高风险、未知类型或预览不完整的操作转手机处理；手表仍可拒绝 |
| 最近记录与手机接力 | 找回最近的问题、笔记和结果，继续原会话或到手机看全文 | 默认至多 10 条最近记录，明确来源和更新时间；草稿/未同步笔记另行保留，不因列表上限被清掉；接力准确定位到对应内容 |
| 快捷动作 | 运行手机中配置的完整快捷消息，例如「用三句话解释番茄工作法」 | 在手机 Apple Watch 设置中添加、编辑和删除完整问题，并选择最多 4 个；过滤只有路由标记的预置消息；按稳定 ID 获取最新定义；修改或删除后及时反馈；发送前可确认内容，仍走相同执行和审批链 |
| 提醒与触感 | 任务结束、需要回答或执行失败时得到提示，点开对应任务 | 通知可关闭；同一任务事件去重；前台交互提供轻触反馈；不因离线旧状态重新同步而重复提醒 |
| 表盘与智能叠放入口 | 从表盘一按进入提问，或直接看当前任务 | WidgetKit 圆形入口和矩形任务卡；任务卡展示最近状态、时间和待处理标记；点击定位到原任务；旧数据明确过期 |
| 连接、隐私与基本设置 | 知道手机是否可用，控制通知、触感和外部内容预览 | 设置页显示连接状态和最后同步时间；默认表盘/通知只显示泛化状态；清除 Watch 缓存前说明不会删除手机会话，并保护未同步输入 |

语音首版含义是「系统听写成文字，确认后发送」。听写和键盘受设备、语言及系统可用性影响，不能把不支持的输入方式画成可用按钮。[Apple：Enter text on Apple Watch](https://support.apple.com/guide/watch/enter-text-apdaf7837856/26/watchos/26)

快捷动作是用户配置的预填问题，不是固定的「翻译」等独立功能。Watch 不创建默认翻译动作；目前尚未单独设置手表选择时，沿用手机已有且支持的前 4 条快捷消息。普通首页预览不注入快捷动作，布局验证的样例只出现在明确的 DEBUG 测试场景中。

## 4. 页面与信息层级

采用原生导航和纵向滚动，首页进入详情后即可完成核心操作。先按功能组织，不在这一阶段固定装饰性视觉稿。

| 页面 | 首屏内容 | 后续内容和操作 |
| --- | --- | --- |
| 首页 | Amber、连接提示、主按钮「问 Amber」、次入口「随手记」 | 如有待回答任务则优先突出；当前任务卡、快捷动作、最近记录和设置入口 |
| 输入页 | 当前模式「新问题 / 继续对话 / 随手记」、输入框 | 识别结果预览；问答为「发送」，笔记为「保存」；返回保留草稿；不能悄悄切换模式 |
| 任务 / 对话详情 | 对话标题、真实状态、最近更新时间 | 先呈现简短回答或需要处理的问题；再提供追问、合适的控制和「在 iPhone 继续」 |
| 最近记录 | 标题、类型、时间、短预览及未读/待同步状态 | 点入详情；无记录时给出提问与记事入口；不会自动同步整库全文到手表 |
| 设置与连接 | 手机连接、配置是否就绪、最后同步时间 | 通知与触感、隐私预览、清理缓存、版本和首次设置说明 |

iPhone 设置中同时提供「Apple Watch」入口：显示同步状态，明确手表使用的已配置助手，添加、编辑、删除快捷消息并选择最多 4 个显示在手表，并查看/整理同步来的 Watch 记事。模型凭据继续在手机原设置中维护；手表追问沿用原会话助手，新问题使用这里确定的助手。独立记事有可找到的手机落点，不能只同步到一个没有 UI 的文件。

iPhone 详情页分为「设备与助手」「快捷动作」「记事与提醒」三组，复用设置主页的图标、文字列、行高和分隔线。入口不附加其他同级设置没有的副标题；记事默认显示数量与状态，展开查看预览，点入全文。辅助功能字号下控件转至正文下方，不挤压正文。

视觉要求：沿用 Amber 标识和暖色强调色，使用 watchOS 原生控件、黑色背景及清晰文字层级。重要状态同时使用文字与符号，不能只用颜色。适配项目支持的小屏、大屏、辅助功能字号、VoiceOver、减少动态效果和低亮度/常亮场景；避免常驻动画与逐 token 闪动。

现有手机图标已经提供 1024×1024 源图。首选直接复用并检查圆形安全区；需要调整构图时再生成适合 Watch 的资源，不另造一套品牌。Xcode 支持从单张高分辨率图生成 watchOS 图标变体。[Apple：Configuring your app icon](https://developer.apple.com/documentation/xcode/configuring-your-app-icon)

## 5. 必须打通的用户流程

### A. 抬腕提问

表盘或首页 → 问 Amber → 系统输入 → 检查文字 → 发送 → 手机确认接收 → 运行 → 简短结果 → 可继续追问或到手机看全文。

- 发送后立刻保存本地请求身份和文字；超时不直接新建第二个请求。
- 如果手机尚未配置模型，提示在手机完成配置，保留问题。
- 如果手机执行入口当前无法安全开始，显示「需要在 iPhone 继续」或「手机正在处理其他任务」，不能一直转圈。
- 普通问答优先返回适合手表的短回答。超过显示范围时明确标为「回答节选」，不得用截断内容伪装摘要；完整内容保存在手机。
- 正常可达场景不能把每个普通问题都退化成「请先打开手机」，否则此项不通过首版验收。

### B. 离线记事

随手记 → 输入 → 保存 → 本地持久化成功才显示「已存手表，待同步」 → 手机重新可达时传送 → 手机持久化成功并确认后显示「已存 iPhone」。

- 手机端增加明确的「Watch 记事」落点，以轻量原文记录保存，复用项目现有文件持久化方式。现有会话库是聊天容器，记忆库具有长期记忆和授权语义，两者都不直接当普通笔记箱使用。
- 保存链路不调用聊天发送或记忆抽取；用户之后明确选择「交给 Amber 处理」时才创建对话。记事的来源和同步身份始终可追溯。
- 传输层投递成功不是手机内容已经写入成功；最后状态需要应用层回执。
- 连续重试、断连、两端重启不能重复创建笔记，也不能丢原文。
- 1.0 不提供双端同时编辑同一条笔记：保存前可编辑草稿；保存后保留原文，修改时另存一条，避免已开始传输的同一 ID 对应不同内容。

### C. 接到任务追问

收到提示 → 打开指定任务 → 阅读完整问题及必要上下文 → 选项或短文字回答 → 手机确认 → 原任务继续。

问题已失效、任务已结束或手机已先回答时，显示最新状态并清除旧操作。若内容无法在手表完整判断，只给手机接力入口和拒绝/跳过等适用操作。

### D. 查看与控制任务

首页任务卡或智能叠放 → 阶段与更新时间 → 查看回答 / 取消任务 / 重试允许恢复的失败任务。

取消不清空已经生成的内容；重试必须验证失败任务仍可重试；老任务的按钮永远不能作用于后来创建的任务。列表切换不影响手机当前正在执行的内容。

工具副作用结果未知时使用独立的「在 iPhone 核实」入口，不当作普通失败或审批，也不提供取消或重试。核实某一工具是否生效不等于整个任务完成；同一任务有多项待核实结果时，剩余项在重启后仍须能找回。旧版本误写的失败缓存可按该任务的明确恢复证据纠正。

### E. 在 iPhone 继续

手表点接力 → 保存带稳定目标 ID 的待接力状态 → 手机可用时进入目标 → 手机确认页面已接管。

在确认前使用「请在 iPhone 打开 Amber 继续」或「已发送到 iPhone」；只有观察到目标页面接管后才使用「已在 iPhone 打开」。手机暂时未展示页面时，接力目标应保留到下一次打开应用，且不能被重复消费或串到别的会话。

## 6. 手机、手表和离线状态的分工

| 场景 | 手表应允许 | 应显示的边界 |
| --- | --- | --- |
| 手机可达、配置有效 | 发起短问答、读取更新、执行可用控制 | 收到真实回执后再前进到相应状态 |
| 手机可达但模型请求失败 | 看失败原因、保留输入、按条件重试 | 区分网络失败、认证/配置失败和任务不再可重试 |
| 手机无法连接 | 看已缓存记录、保存笔记、编辑问题草稿 | 问题待用户重新发送；取消/审批/重试不排队，不在几分钟后偷偷执行 |
| 已发送但回执丢失 | 查原 requestId 的处理状态 | 显示「正在确认是否已接收」，不直接把超时当作未执行并重复发送 |
| 手机后台资源不足或进程中断 | 显示已保存的结果及可恢复状态 | 不能承诺任意模型/工具均持续运行，恢复能力取决于真实执行路径 |
| 手机锁定、需要权限或前台工具 | 保存上下文、提示到手机处理 | 不把能唤醒手机进程当作能解锁或强制展示页面 |
| 两端版本不兼容 | 本地读取与草稿；给出更新提示 | 禁止执行不认识的命令 |

WatchConnectivity 可以在符合条件时从手表唤起手机应用的后台处理，但不提供无限后台执行保证。最新状态适合使用 application context；需要逐条确认的记事另用可靠传输和应用层回执。继续保留现有互动控制命令不离线排队的约束。[Apple：Transferring data with Watch Connectivity](https://developer.apple.com/documentation/WatchConnectivity/transferring-data-with-watch-connectivity)

通知首版复用 iPhone 通知和系统转发，补齐事件身份、深链与去重；不同时在两端重复安排同一条提醒。最终投递位置受设备锁定和系统设置影响，不能承诺两端同时提醒。[Apple：Taking advantage of notification forwarding](https://developer.apple.com/documentation/watchos-apps/taking-advantage-of-notification-forwarding)

表盘和智能叠放需要 Watch 自己的 WidgetKit 扩展和可读缓存；不把手机 Activity Widget target 当作已经实现。时间线刷新由系统调度，产品展示更新时间，不承诺每秒更新。[Apple：Creating accessory widgets and watch complications](https://developer.apple.com/documentation/widgetkit/creating-accessory-widgets-and-watch-complications)

## 7. 操作与隐私规则

- 1.0 手表批准范围限定为只读搜索/读取网页，且查询词或目标地址、所用服务和发送内容必须能完整展示；信息选择与短回答使用独立的追问流程。未知类型和其他工具默认到手机确认。实现时按操作及参数判定，不能仅依赖 `riskLevel` 文案。
- 外部发送、删除、Shell/SSH、插件执行/导入、凭据和账户操作等需要到手机完整确认；手表可以拒绝。缩短预览不能改变审批边界。
- 新问题、继续回答、记事、快捷动作都绑定稳定请求 ID；任务控制额外校验 runId、conversationId、decisionId 及有效期。状态接受有顺序，旧包不能覆盖新决定或新终态。
- 同步最小必要内容，不传 provider API key、原始工具参数、完整会话库或 HealthKit 数据；手表录入的普通问题会按用户已有手机模型配置处理，首次使用应明确说明。
- 问题和笔记要区分：保存笔记不等于调用 AI，也不等于创建系统提醒或写入长期记忆。
- 表盘、常亮和通知默认使用泛化状态；用户开启内容预览后仍遵守系统隐私展示。清理缓存必须先处理未同步内容，不能静默丢弃。

## 8. 1.1 与后续范围

这些功能有价值，但不阻塞上述 1.0 闭环；实现前需单独补齐对应数据与系统验证。

| 功能 | 推迟原因与进入条件 |
| --- | --- |
| 今日简报 | 当前手机入口主要是提交一段 prompt，不是已有结构化简报服务；先定义可用数据、读取授权、更新时间与缓存。首版不自动复用其中提及 HealthKit 的提示词 |
| Siri 参数化提问与运行指定快捷动作 | 需要 Watch target 的 App Intent、实体解析、输入与唤起路径证据；手机的 Intents 文件不等于手表已支持 |
| 轻量朗读回答 | 用户主动播放、可立即停止；先验证 watchOS 音频路线、静音习惯和后台行为，不默认外放 |
| 笔记转提醒 / 日程 | 需要明确日期、目标列表、用户确认和提交后读回；在基本记事可靠后复用手机 EventKit 能力 |
| 更长的历史、固定某个对话到表盘 | 待短交互模式稳定，再扩充选择和缓存范围 |
| 离开手机仍独立联网对话 | 是另一条执行架构：需要 Watch 的凭据生命周期、网络/provider 支持、能耗、恢复和独立安装验证；当前工程明确为伴侣应用 |
| 实时双向语音、健康/运动助手 | 分别需要音频会话和健康数据产品闭环；不由「完整 Watch 应用」自动推导成首版需求 |

## 9. 实施顺序与验收

按四段推进，但四段全部通过后才算 1.0 完整。

1. **能装、能认、状态可信**：补图标与工程资源、首页/首次使用/连接页、缓存和过期展示；修正审批范围与手机接力的错误成功提示。
2. **能发起、能保存、能收到**：完成新问题和追问、记事的本地保存与同步、真实接收回执、忙碌/中断/重试路径。这是首版最关键的交付门槛。
3. **能找回、能控制、能复用**：最近记录、原任务控制、手机接力和手机配置的快捷动作。
4. **抬腕即用且可发布**：通知、触感、表盘与智能叠放、多语言、辅助功能与双设备回归。

验收必须包含：

- [ ] 安装后的应用列表、通知及 Watch 管理入口中图标正确，圆形裁切不伤标识；正式和实验 target 都检查。
- [ ] 无手机配置、无连接、空历史时都给出清楚下一步；不会落到只有刷新按钮的空页面。
- [ ] 手机正常可达时，从手表新建普通问题并收到回答，不依赖每次手动打开手机；追问进入同一会话。
- [ ] 手机忙碌时发起新问题不切走、不覆盖或取消已有任务；输入仍被保存。
- [ ] 离线保存笔记后重启手表，原文仍在；手机接收后重启，记录仍在；多次传输只产生一条。
- [ ] 超时但手机实际已接收、晚到回执、重复点击与乱序状态不会制造重复任务或误报完成。
- [ ] 新决定清除旧答案草稿；过期决定不可操作；高风险或预览不完整的审批只能转手机或拒绝。
- [ ] 取消、失败、partial、中断、过期和重试保留所属会话的已产生内容，旧 run 不影响新 run。
- [ ] 最近记录在重启后仍可读，明确展示缓存时间；手机删除的目标无法继续操作，刷新后正确失效。
- [ ] 接力能恢复到准确目标；手机没有展示目标时不报「已打开」。
- [ ] 通知点入原任务，旧快照重放不重复提醒；关闭通知与预览设置后实际生效。
- [ ] 表盘入口可启动提问，任务卡可定位任务，缓存过期时不展示误导状态。
- [ ] 最小支持屏幕、大屏、VoiceOver、辅助功能字号及减少动态效果下可完成核心流程；固定文案跟随现有六语言支持。
- [ ] 两端系统权限、配对通信、后台/锁屏、抬腕放腕、真实 provider 和通知转发均有真机记录；模拟器结果不能代替这些证据。

技术验证优先复用 `WatchTaskSnapshotTests`，为新增输入持久化、幂等接收、草稿生命周期、版本兼容和 Widget 路由补充对应行为测试，并增加 Watch 页面状态测试。工程继续以 `project.yml` 为唯一配置源；只修改涉及的所有者，不把功能堆入 ChatView 或创建另一套 provider 引擎。

实施记录：已按用户选择的场景 1 和 2 完成 Watch、共享通信及 iPhone 消费入口的首版实现。137 个相关行为用例已分轮通过，正式/实验 Watch target 已构建运行，新增 158 个固定文案具备六语言资源。详见 [实施与验证记录](../reviews/2026-09-08-amber-watch.md)。设备相关验收项仍未勾选，不能将模拟器结果当作真机发布验收。

## 2026-09-08：成果优先首页（用户选定暖白方案）

首页将「最近干了什么」放在第一位：暖白成果卡显示真实任务标题、摘要和完成时间，正在运行／等待回答的当前任务优先呈现。下方进入「近期动态」，主提问按钮固定在首页底部，记事、草稿、快捷动作和设置保留在可滚动区域。

近期动态来自手机持久保存的真实终态运行及手表原始记事，不把任意聊天预览当作完成事件。手机最多保留最近 20 项终态，推送最新 10 条活动；本地原始记事继续保留。失败、取消、记事待同步分别标记。结果已读状态在手表保存，读过不会移除成果；详情持有原条目，后续库更新不会把正在看的内容换成另一个 run。

实时成果摘要覆盖已接入 WatchTaskCoordinator 的聊天与后台任务。旧 durable run 可以恢复终态和完成时间；没有可靠结果关联时只能显示通用状态，不能将最近一条聊天消息伪装成原任务成果。独立功能的完整成果封面／专用目的页并未因此自动接入。已有 conversationId 的记录可追问原会话或通过既有接力入口在手机继续。

卡片标题是两行预览，详情展示完整可用文本；小表及大字号优先正文，隐藏装饰纸页。样例行程只存在于隔离 DEBUG 视觉场景，不进入生产历史。

## 2026-09-08 最新成果首页约定

用户最终选择深铜色文字成果卡，取代暖白插画方案。首页按真实当前任务/最近终态记录显示状态、完成时间、两行题目与一行摘要，点击打开完整内容；只有测试启动参数才展示固定样例。小应用保存成功后可以携带独立成果名称，普通任务与无法安全迁移的旧记录仍显示真实会话标题。

连接可达与某次同步是否成功是两个事实：恢复连接后移除旧连接失败提示，当前同步失败明确标注本次同步未完成；未确认是否送达的请求不得因为重连而清除。首页与设置使用同一连接展示状态。
