# 手机控制易用性改进（2026-10-11）

## 基线与范围

用户已明确确认本机自动化真机闭环成功。本轮在既有 LocalDevVPN、配对、手机自主 runner、签名工具及 2000 节点观察上改进使用体验。该确认是用户行为验收，不补造之前未运行的只读诊断结果。

需求：免除每次手动开启授权窗口；本机发现 App 名称和 Bundle ID，由设置或 Agent 添加；灵动岛清楚显示自动化阶段及结束。

保留当前 dirty/untracked 工作。只修改本 iOS 产品。继续开发、验证和原位安装已获授权；未要求提交、推送或发布。本轮不重放过去的办公消息。用户要求每个 phase 独立 subagent review，修正后再继续，不因普通实现选择停下来询问。

## 已确定方案

- 直接采用现有持久化手机控制总开关；开启后新用户任务可用，取消独立授权按钮和时间窗口。任务取消只结束本轮，关闭总开关立即停止当前控制；重启恢复开关和所选应用，不恢复旧任务。
- 本机应用目录走已验证的 RemotePairing→TLS→RSD→InstallationProxy Lookup；不启动目标 App 或 XCTest。设置中搜索选择应用，名称为主、Bundle ID 为辅。Agent 用明确的查询/添加操作复用同一目录；添加到持久范围后可在当前任务使用，不要求另起任务。
- 复用现有 Live Activity 的 runId 所有权、阶段和结束机制。连接、读取界面、打开/点击/输入/滑动、等待模型及停止要与真实执行事件对应。执行回执不等同于业务成功；失败和结果不确定不能记为完成。不显示假百分比，不显示联系人或输入内容。
- 不新增第二套权限体系、不更换 runner、不自动选择不明 App、不静默扩大到所有应用、不增加动作重放。保留单任务 owner、前台/PID/最新 ref 检查及 unknown 后停止。

Devin Opus 5.5 只读复核完成（`agent-64d27c71bcb4c9b46b25647f76b9e77f`）。采纳：已有 runner 时复用启动时获取的应用目录，避免并行第二条隧道；Lookup 限定所需属性；回执到达后立即发布等待或失败状态。手机阶段优先复用现有 stage 和 detail，避免不必要的 Watch 枚举兼容分支。用户已要求 Agent 自行填写应用并去除反复授权，采用精确目录匹配后自动添加，不新增确认。

## Phase 1：总开关直接启用

删除授权窗口 UI、计时状态和调用链；工具接入只取持久开关及新用户任务条件。配对和范围不足由实际工具清楚报告，避免工具凭空消失。停止/失败/取消与新任务隔离。

验收：开关重启后仍有效；无手动授权即可获得声明并 claim；关闭立即取消匹配任务；旧 run 收尾不影响新 run；冷恢复和子任务不悄悄恢复控制。设置页布局紧凑，状态与操作可读。

检查：Controller、Catalog、Executor、Settings Wiring 定点测试；设置页视觉检查；独立 review 后修正。

## Phase 2：本机应用发现与添加

增加有界、可取消的本机应用目录查询；名称和 ID 正规化；设置页搜索、选择、移除、错误/空/加载状态，保留高级手填入口。Agent 通过工具发现真实 ID 并添加到当前和持久范围。没有控制会话时短查询不启动 runner；已有会话时读取启动时获取的目录，不建立第二条隧道。添加后不需电脑或重启任务。

验收：手机自身取得目标 App 名称及 ID；查询无操作副作用；精确 ID 添加一次且同轮可用；关闭/旧任务迟到返回不能改范围；重启保留选择；列表支持长名称、大字体与键盘。

检查：native 目录解析/取消/错误测试、Swift 注入测试、工具契约与范围更新测试、设置 UI 检查；独立 review 后修正。

## Phase 3：自动化进度与结束

从真实 executor 事件发布手机阶段到既有 Live Activity。工具回执后及时显示等待模型；停止、失败、不确定和整体完成有明确终态。修正步骤历史将失败误标完成的情况。沿现有 runId 防止迟到事件串任务。

验收：启动/观察/输入/等待可区分；完成后不继续显示正在操作；失败不打成功勾；取消会结束活动；compact/minimal/expanded/锁屏及大字体无挤压错位。

检查：展示映射、步骤历史、终态和迟到事件测试；widget 渲染/截图检查；独立 review 后修正。

## Phase 4：集成与交付

一次正式 Release 构建、签名核验、原位安装，保护数据。检查总开关跨重启、手机本机查询应用及 UI/工具添加闭环、灵动岛阶段与结束。按实际结果区分代码/测试/模拟器/真机证据；系统锁屏等外部条件如确实阻断，完成其他验证并明确记录，不能假称通过。

最终独立 review 与一次有限维护性检查；修正真实问题后重跑受影响检查。不追加无关优化。

## 使用方式

1. 在手机自主控制页面开启总开关，后续新任务直接获得手机工具。停止一次任务不关闭总开关；手动关闭总开关立即撤销当前控制。
2. 在「从本机选择 App」中按名称搜索添加；也可让 Agent 查询 `phone_apps` 并用返回的准确 ID 调用 `phone_add_app`。无须电脑查 Bundle ID。目录查询失败会显示原因，保留重新读取和高级手填入口。
3. 灵动岛区分连接、读取、打开、点击、输入、滑动及等待模型；未知结果显示「待核对」，不显示成功或重试入口。整轮完成/停止沿既有 Live Activity 终态收尾。系统 XCTest 自动化指示与 Amber 的 Live Activity 是不同界面；本轮不宣称改变 iOS 自身的指示行为。

- Phase 4 交付结果：Release 构建成功，deep/strict 签名验证通过，Bundle ID `app.amber.ios` / 原 Team 保持一致；正式包不含模拟器预览入口，已成功原位安装。安装前后 352 个会话文件路径、大小和修改时间一致；6 项 extendedAttributes 有变化，未读取内容做哈希；App Group 根目录元数据一致。
