# Prompt Cache 5m 净账与 85% 压缩保真基线（2026-11）

- **测试日期**：2026-11-22
- **受控基准夹具**：`cloud-daemon/src/jvmTest/kotlin/app/amber/cloud/PromptCacheBaselineBenchmarkTest.kt`（20 条使用合成文本的会话夹具，含短问答对照，`S01`–`S20`）与 `ai-provider-claude/src/jvmTest/kotlin/app/amber/ai/provider/claude/ClaudePromptCacheBaselineTest.kt`
- **复用的真实计量与压缩实现**：
  - `TokenUsage.cacheCreationTokens` + `TokenUsage.estimatePromptCacheInputCost(PromptCacheWriteTier.EPHEMERAL_5M)`（写 `1.25x`、读 `0.10x`、未命中 `1.00x`）
  - `CloudContextManager` + `CompactPolicy(precompactRatio = 0.85f, forceRatio = 0.85f, keepRecentTurns = 4)`（对齐 macOS `DesktopContextBudget.autoCompactionRatio = 0.85` / `scheduleAutomaticCompaction`）
- **全局默认开关结论**：**不强开全局默认 Prompt Cache 开关**（`ProviderSetting.Claude.promptCaching` 保持默认 `false`）。

净变化按相同请求序列比较。每次已计费请求的等效输入成本为 `未缓存输入 + 1.25 × 写入 + 0.10 × 读取`，再除以关闭缓存时所有请求的输入总量并减 1。CloudContextManager 在本地生成摘要，生成过程消耗 0 个模型 token。摘要随之后的请求发送，已计入对应前缀或未缓存输入。S10 第五轮模拟首个请求完成输入计费后连接中断，即时重试增加 3,691 个输入 token，其中 3,687 个命中缓存。两种方案都承担这次重试。表中为受控夹具的输入成本估算，输出费用和线上账单另计。

## 三、关键判断与下一阶段建议

1. **禁止全局默认开启 5m 缓存**：纯冷单轮与 >5 分钟间隔的稀疏问答（`S01`–`S03`）会产生 **+24.9% 至 +25.0%** 的净成本惩罚（组均值 **+5.1%**）。保持 `ProviderSetting.Claude.promptCaching = false` 默认值，后续只对**连续多轮工具循环 / 后台 Worker 任务**按策略开启。
2. **连续工具调用收益极高，跨 85% 压缩存在重建折损**：热前缀工具循环净降本 **-72.1%**；跨越 85% 压缩边界后因 `<context-handoff>` 替换旧前缀触发缓存重写，净降本收敛至 **-39.1% ~ -48.1%**（高频连续压缩的 `S12` 为 `-29.0%`）。
3. **压缩保真盲区清晰可修**：当前 `CloudContextManager.extractMustNotLose` 能 100% 保留路径/错误码/Commit SHA 及首 160 字规则（`9/9`），但对埋在长段末尾的纯自然语言硬约束（`S18`/`S19`）保留率为 `0/3`。建议在下一阶段给 `extractMustNotLose` 增补显式约束句型提取（如 `必须/禁止/不要/严禁/仅限/MUST/NEVER`）并复跑同一 20 条基线夹具验证提升。
