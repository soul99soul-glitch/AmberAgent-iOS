# ai-memory 跨设备记忆工作台

独立的本地 Web 面板，使用已安装的 `ai-memory mcp-bridge --no-session-id` 连接现有服务。浏览器只访问本机面板后端；ai-memory 凭据不传给浏览器。面板没有依赖安装步骤，不含虚构的演示数据。

## 本机打开

需要 Node.js 18+、已配置并可连接的 ai-memory CLI（本机已用的配置和认证会由 ai-memory 读取）。双击 `打开记忆面板.command`，或在终端运行：

```sh
./start.sh --open
```

访问 `http://127.0.0.1:47890`；保持终端窗口运行，按 Ctrl-C 停止。其他系统可运行 `./start.sh` 后手动打开该地址。可设置 `PORT` 更改端口、`AI_MEMORY_CLI` 指向 CLI。服务固定只监听 `127.0.0.1`。如果本机通过 SSH 隧道连接云端，请先确保原有隧道已连接；面板不会修改或重建隧道。

默认项目 `default/amber`；可切换 `default/mi`、`_global`、Profile 和输入其他项目。请核对自定义项目名：上游写入接口可能自动创建不存在的项目。

## 腾讯云运行及跨设备访问

在云端准备好 Node.js 18+ 和已经安装、配置好连接与权限的 ai-memory CLI；将本目录复制到云端后，登录同一用户运行 `./start.sh`。不要提交或复制本机凭据文件到代码目录。按云端现有 ai-memory 安装方式设置 `AI_MEMORY_SERVER_URL` 和令牌文件或使用已有 CLI 配置；切勿把令牌放在命令行参数、前端代码或 README 中。

推荐通过 SSH 转发访问面板，无需开放 Web 端口：

```sh
ssh -N -L 47890:127.0.0.1:47890 <云端用户>@<云主机>
```

在客户端打开 `http://127.0.0.1:47890`。要常驻运行，可通过现有进程管理器以专用用户运行 `start.sh`，并保证该用户能读取既有 ai-memory 配置。若确需域名访问，必须在受信任的反向代理上先配置 HTTPS 和可靠的身份认证，再设置 `PANEL_ALLOWED_HOSTS` 为允许的 `Host`（多个用逗号分隔）；切勿将该面板或 ai-memory 服务裸露公网。面板自身不提供登录功能，也不终止 TLS。

## 能力与限制

- 待接力列表、作废、共享交接；会话按最早可见事件排列，并显示原始记录和来源设备。最早捕获事件不保证是完整工作区间，补传数据要结合会话总结确认。
- 项目知识页按目录分类、置顶优先，支持 Markdown 安全预览、新建、编辑、置顶和删除。创建使用 `create_only`，编辑/删除使用 `expected_page_id`；编辑保留可由接口读取的常用元数据。超过 64000 字符的页面只读，防止覆盖未加载部分。最近页面接口最多返回 100 项，更早页面使用搜索。
- 按关键词、类型、路径以及过期/历史版本搜索。历史搜索结果打开的仍是当前页面版本，界面会注明。
- Checkpoint 通过 `memory_restore_page` 查询与回滚。它需要上游允许管理员操作。该接口未提供按 rev 读取完整正文，因此面板显示 Checkpoint 元数据，无法做逐字历史对比；回滚前检查当前页面版本，但上游恢复操作没有原子 `expected_page_id`，检查与恢复之间仍有竞态。
- Profile 列表由 `ai-memory profile list` 提供；多用户服务器通常要求 root。当前 CLI 用户对 Profile 和 Checkpoint 实测返回 403，界面会如实显示。`_global` 尚未创建或无权访问时也会显示上游错误；不会代用户创建作用域或提高权限。
- 所有删除、作废、回滚均需在界面单独确认。写入、删除、回滚及权限均由 ai-memory 服务最终裁决。
